# reconcile_dbs fixtures

`reconcile_dbs` (project DB <-> shared `allprj` DB missing-event
reconciliation) needs no fixture files of its own: its Go <-> Rust compat
suite (`rust/cmd/reconcile_dbs/tests/compat.rs`, 41 cases) creates every
source and target database of both sides from
`rust/compat/fixtures/structure/full_structure.sql` and seeds them from SQL
generated by the test (`seed_sql`, `event_sql`, `commit_sql`).

The seeded "world" is deterministic and fully described by the constants at
the top of the test file:

- `E1`..`E7` — native events of repositories 101, 102, 104 (in the target)
  and 103 (source only, out of scope), spread over the last days (per-day
  buckets): `E1` is present on both sides, `E2`/`E3`/`E7` are missing in the
  target (push with commits, issue with label + comment, pull request with
  review), `E4` is older than the default 90-day window, `E6` belongs to a
  repository without an organization.
- `A1` — an artificial (2^48-based id) event, copied only with
  `GHA2DB_RECONCILE_ARTIFICIAL`.
- `O1`, `O2` — orphan (negative id, restored) pushes: `O1`'s commit is
  already present on the target (under `T1`), so it is always skipped;
  `O2` brings a new commit.
- `T1` — a target-only native push: its day is never examined, because only
  the source's buckets are compared (one-directional pull by design).
- `S1`, `S2`, `T2`, `N1`..`N3` — the "take over" scenario: synthetic pushes
  (`S1`, `S2`) in the target whose commits get taken over by the native
  pushes (`N1`, `N2`) arriving from the source; the emptied `S1` is removed,
  `S2` keeps its remaining commit; `T2`/`N3` share a commit natively.

The project filter (the target project's `command_line` org/repo lists or
`regexp:` patterns, `GHA2DB_EXCLUDE_REPOS`, `GHA2DB_EXACT`, actors filter —
the same rules `gha2db` applies when it ingests events for that project) is
exercised by the `events_outside_the_project_org_list_are_not_copied`,
`org_and_repo_lists_and_the_exclude_list_are_applied`,
`regexp_and_actor_rules_are_applied`,
`a_second_run_after_filtering_copies_nothing_more` and
`explicit_mode_applies_the_yaml_rules_when_present` (explicit sources, dry
run) cases: they write a `projects.yaml` whose `alpha` project owns the
target and has a restrictive `command_line`/`env`, then check the
`filter: project 'alpha': …` header line, the per-source `filtered out N event(s) outside project 'alpha'
org/repo/actor rules (native a, orphan b, artificial c)` line, the
`filtered out N event(s)` field of the total line and the exact set of
event ids that made it into the target (repository 104 `solo/repo4` has no
organization, so an org list of `org1` drops it; `O1` lives in `org1/repo1`,
so a `repo2`-only rule drops the orphan before the commit check). The shared
direction is covered by `shared_mode_applies_the_shared_projects_own_rules`
and `shared_mode_with_a_child_project_name_still_uses_the_shared_projects_rules`:
the shared database's own project (`selfref`, with an org list and
`GHA2DB_EXCLUDE_REPOS`) decides what is pulled from the children — also when
`GHA2DB_PROJECT` names a child — so the children may track more, fewer or
different repositories than the shared project. Without a `projects.yaml`
the header reads `filter: none (no ./projects.yaml)`; with one where no
enabled project owns the target it reads `filter: none (no enabled project
uses this database in ./projects.yaml)` and nothing is filtered
(`explicit_mode_without_an_owning_project_filters_nothing`).

The postprocess step reads `util_sql/postprocess_{texts,labels,issues_prs}_ids.sql`
from `rust/compat/fixtures/get_repos/util_sql/` (via `GHA2DB_DATADIR` or
`GHA2DB_LOCAL`), exactly like `get_repos` does.

The suite compares, for every case: the exit code, the full masked stdout
(dates in `since <ts> (range …)` headers and in failing-query argument
echoes `[1:<ts> …]` are masked, Go durations are masked by the shared
`mask_go_durations`), the `Error:`/`PqError:` stderr lines and a full
snapshot of every target-DB table (with `gha_repos` compared through an
explicit column list because of its `now()`-defaulted timestamps).

Failed cases keep their `dbtest_reconcile_*` scratch databases for
inspection; drop them by hand once done.
